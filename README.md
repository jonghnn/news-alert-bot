# 관심사 알림 봇

유튜브 채널 · 뉴스 키워드 · 웹사이트를 30분마다 확인해서, **내 키워드에 맞는 새 글만** 텔레그램으로 보내줍니다.

- 내 컴퓨터를 켤 필요 없음 (GitHub 서버에서 자동 실행)
- 전부 무료 (API 키·결제 수단 불필요)
- 한 번 보낸 글은 다시 오지 않음
- 소스 추가/삭제는 [`config.yml`](config.yml) 한 파일만 수정

> 🛠 **개발/인수인계 문서는 [STATUS.md](STATUS.md)** — 지금까지의 결정사항, 실측 데이터,
> 고친 버그, 남은 일, 로컬 테스트 방법이 정리돼 있습니다.

## 설치 (한 번만, 약 10분)

### 1단계 — 텔레그램 봇 만들기

1. 텔레그램에서 **@BotFather** 검색 → 대화 시작
2. `/newbot` 입력 → 봇 이름과 아이디(`_bot`으로 끝나야 함) 입력
3. 답장으로 오는 **토큰**을 복사해 둡니다 (`8123456789:AAF...` 형태)
4. BotFather가 알려준 `t.me/내봇아이디` 링크를 눌러 **내 봇과 대화를 시작**하고 아무 메시지나 하나 보냅니다
   → 이걸 안 하면 봇이 나에게 메시지를 못 보냅니다

### 2단계 — GitHub에 올리기

1. [github.com](https://github.com) 가입 후 오른쪽 위 **+ → New repository**
2. 이름은 아무거나 (예: `my-alert-bot`), **Public** 선택 → *Create repository*
   > ℹ️ Public이면 실행 시간이 **무제한 무료**입니다. Private은 월 2,000분 한도라 30분 주기로는 부족할 수 있어요.
   > 비밀번호·토큰은 코드가 아니라 3단계의 Secrets에 들어가므로 Public이어도 안전합니다.
3. 새로 만든 저장소 화면에서 **uploading an existing file** 링크 클릭
4. 이 폴더(`텔레그램봇`)의 **내용물 전체**를 드래그해서 올립니다
   > ⚠️ 폴더째로 올리지 말고 **안에 있는 파일·폴더들**을 선택해서 올려야 합니다.
   > `.github` 폴더가 안 올라가면 자동 실행이 안 되니 꼭 포함되었는지 확인하세요.
5. 아래 **Commit changes** 클릭

### 3단계 — 비밀값 등록

저장소의 **Settings → Secrets and variables → Actions → New repository secret** 에서 두 개를 만듭니다.

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계에서 복사한 토큰 |
| `TELEGRAM_CHAT_ID` | 4단계에서 확인 (일단 아무 값이나 넣고 나중에 수정) |

네이버 뉴스를 쓰고 싶다면 두 개를 더 등록합니다 (**안 쓰면 생략해도 됩니다**):

| Name | Secret |
|---|---|
| `NAVER_CLIENT_ID` | [네이버 개발자센터](https://developers.naver.com/apps/#/register)에서 발급 |
| `NAVER_CLIENT_SECRET` | 같은 화면에서 발급 |

### 4단계 — 내 chat_id 확인

1. 저장소 상단 **Actions** 탭 → 왼쪽 **알림 봇** 클릭
   - "Workflows aren't being run on this forked repository" 같은 안내가 나오면 초록 버튼을 눌러 활성화합니다
2. 오른쪽 **Run workflow** → mode를 **chatid** 로 바꾸고 실행
3. 실행이 끝나면 클릭해서 로그를 펼치고 `chat_id = 123456789` 를 찾습니다
4. 그 숫자를 3단계의 `TELEGRAM_CHAT_ID` Secret에 저장합니다

### 5단계 — 연결 확인

**Actions → 알림 봇 → Run workflow → mode: test** 실행
→ 텔레그램으로 `✅ 알림 봇 연결 성공` 이 오면 끝입니다.

이제 30분마다 알아서 돌아갑니다. 별도로 할 일은 없습니다.

> 💡 **첫 실행은 알림이 오지 않습니다.** 과거 글 수십 개가 한꺼번에 쏟아지는 걸 막기 위해,
> 새로 추가된 소스는 기존 글을 "이미 본 것"으로 기록만 하고 넘어갑니다.
> **그 이후에 올라오는 글부터** 알림이 옵니다.

## 소스 추가 / 제거

`config.yml` 을 GitHub 웹에서 직접 수정하면 됩니다 (파일 클릭 → 연필 아이콘 → 수정 → Commit changes).
잠시 뒤 다음 실행부터 반영됩니다.

### 유튜브 채널

```yaml
  - name: 채널 이름
    type: youtube
    channel: "@핸들"        # 채널 주소나 UC로 시작하는 채널ID도 됩니다
    enabled: true
```

핸들은 유튜브 채널 페이지 주소에서 `youtube.com/@여기` 부분입니다.

### 뉴스 키워드

```yaml
  - name: 전기차 소식
    type: news
    query: '전기차 OR "배터리 충전" -중고'
    lang: ko
    country: KR
    enabled: true
```

검색어 문법: `"큰따옴표"` = 정확히 일치, `OR` = 둘 중 하나, `-단어` = 제외

### 이슈 전개 추적 (구글 뉴스 섹션)

**"같은 이슈인데 새로운 내용이 생겼을 때만" 알림받는 방식입니다.** 위의 키워드 알림과 성격이 다릅니다.

| | `news` (키워드) | `issue` (이슈 추적) |
|---|---|---|
| 알리는 단위 | 기사 하나하나 | 이슈(사건) 하나 |
| 같은 사건 기사 5개 | **5번 옴** | **1번 옴** (묶어서) |
| 그 사건에 새 기사 | 또 옴 | **새로 붙은 것만** 알려줌 |
| 변화 없으면 | 계속 옴 | **안 옴** |

```yaml
  - name: 세계 이슈
    type: issue
    section: 세계        # 세계/국내/경제/기술/과학/건강/스포츠/연예
    max_items: 8
    issue_ttl_days: 7    # 이 기간 안 보인 이슈는 추적 중단
    enabled: true
```

실제로 오는 알림:

```
🌏 세계 이슈 · 🔄 전개 1
"미국, 이란 핵 양보 시 제재 완화 의향"…중재국 통한 물밑 협상
새 기사 4건:
· 美·이란 '7일 계획' 놓고 줄다리기 (v.daum.net)
· 미-이란, 중재국과 '7일 휴전안' 논의 (머니투데이)
· 미-이란, 중재국 통해 협상 계속…사우디 송유관 가동 재개 (한겨레)
```

`🆕 새 이슈` = 처음 등장한 사건, `🔄 전개 N` = N번째로 새 내용이 붙었다는 뜻입니다.

**작동 원리:** 구글 뉴스 섹션 RSS는 같은 사건 기사를 언론사별로 묶어서 줍니다.
그 묶음을 저장해 두고 다음 수집 때 비교해, 새로 붙은 기사만 알려줍니다.
키워드 `include` 는 적용하지 않습니다 (섹션 선택 자체가 범위 지정이므로). `exclude` 는 적용됩니다.

#### 어느 섹션을 켤까 — 묶음이 없어도 켤 가치가 있습니다

섹션마다 구글이 묶음을 만들어주는 비율이 다릅니다 (이슈 478개 실측):

| 섹션 | 묶음 생기는 비율 |
|---|---|
| 국내 · 경제 | 91% |
| 연예 · 스포츠 | 90% |
| 세계 | 79% |
| 건강 | 27% |
| 기술 · 과학 | **0%** |

**하지만 묶음이 없다고 쓸모없는 게 아닙니다.** 묶음이 없으면 기사 1건이
`🆕 새 이슈` 로 **한 번만** 올 뿐입니다. 중복 없이 한 번 오는 것 자체로 충분히 유용합니다.

실제로 투자·AI 키워드로 걸러본 결과(하루 예상 건수 기준):

| 섹션 | 키워드 통과 | 하루 | 묶음 | 비고 |
|---|---|---|---|---|
| 경제 | 24개 | 22건 | 22개 | 이슈 전개 추적이 제대로 작동 |
| **기술** | 23개 | 13건 | 0개 | **묶음은 없지만 21건이 순증** |
| 세계 | 6개 | 7건 | 5개 | 관세·유가·제재·달러 |
| 과학 | 12개 | 2건 | 0개 | 저렴 |
| 국내 | 2개 | 표본부족 | 2개 | 정치·사회 위주, 오탐 있었음 |
| 건강 | 1개 | 드묾 | 0개 | — |

**기술 섹션은 `type: news` 검색과 겹침이 5%뿐입니다.** 섹션은 구글이 골라준 주요 뉴스,
검색은 키워드에 걸리는 모든 기사라서 선택 방식이 달라 서로 보완됩니다.
예를 들어 *"오픈AI 훈련 멈추자 반도체주 휘청"* 은 AI 키워드 검색으로는 들어오지 않았습니다.

**알아두실 한계 네 가지:**

1. **변화를 "설명"해주지는 않습니다.** 새로 붙은 제목을 나열할 뿐이라, 무엇이 달라졌는지는
   제목을 보고 직접 판단하셔야 합니다.
2. **구글의 묶음이 완벽하지 않습니다.** 실측에서 *"교황, AI 인류위협론 반박"* 이슈에
   *"에어프랑스, 교황에 특별편 제공"* 이 섞여 있었습니다. 같은 인물, 다른 사건인데 묶였습니다.
3. **이슈당 기사 5건이 구글의 고정 상한입니다** (이슈 478개 중 초과 0개). 기사가 쌓이는 게
   아니라 교체되므로, 아주 빠르게 쏟아지는 사건은 중간 기사를 놓칠 수 있습니다.
   기술·과학 섹션은 묶음이 0%라 전개 추적이 아니라 '중복 없는 뉴스 알림'으로 동작합니다.
4. **같은 사건이 🆕 로 두 번 올 수 있습니다.** 이슈 판정은 "기사 링크가 겹치는지"로 하는데,
   30분 사이에 5건이 전부 교체되면 겹치는 링크가 0개가 되어 새 이슈로 오인됩니다.
   전체 이슈의 57%가 상한 5건에 꽉 차 있어 드문 일은 아닐 수 있습니다.
   (아직 실제로 관측하지는 못했습니다 — 30분 이상 돌려봐야 확인됩니다.)

**"새 기사 4건" 의 정확한 뜻:** "지난 30분간 발행된 기사 4건" 이 아니라
**"지난번 봤을 때 그 묶음에 없던 기사 4건"** 입니다. 묶음 안의 기사에는 발행 시각이
없어서(제목·언론사·링크만 옴) 각 기사가 언제 나왔는지는 알 수 없습니다.

### 네이버 뉴스 키워드

```yaml
  - name: 네이버 반도체 뉴스
    type: naver
    query: 반도체
    display: 30        # 한 번에 조회할 개수 (최대 100)
    enabled: true
```

> ⚠️ **네이버 뉴스 RSS는 2022년 3월에 종료됐습니다.** 그래서 RSS 주소로는 받을 수 없고,
> 네이버 **공식 검색 API**를 씁니다. 무료(하루 25,000회)지만 키 2개를 먼저 발급받아야 합니다:
> [developers.naver.com/apps/#/register](https://developers.naver.com/apps/#/register) → 사용 API에서 **검색** 선택 →
> 나온 Client ID / Secret을 위 3단계처럼 Secrets에 등록 (5분)
>
> 키를 등록하지 않으면 이 소스만 **조용히 건너뜁니다** (다른 소스는 정상 동작, 오류도 안 납니다).

**구글 뉴스(`type: news`)와 뭐가 다른가요?** 네이버가 한국 언론사 기사를 더 폭넓게 잡습니다.
대신 키 발급이 필요하고, 검색어에 `OR`·`-제외` 같은 문법은 안 통합니다.
키 발급이 번거로우면 `type: news`(구글)만 쓰셔도 한국 뉴스는 잘 들어옵니다.

### 네이버 블로그

블로그 RSS는 **아직 살아있어서 키 없이** 바로 됩니다:

```yaml
  - name: 어떤 네이버 블로그
    type: site
    url: https://rss.blog.naver.com/블로그아이디.xml
    enabled: true
```

블로그 아이디는 `blog.naver.com/여기` 부분입니다.

### 웹사이트

```yaml
  # RSS 주소를 알면 그대로 넣기 (가장 정확)
  - name: 어떤 블로그
    type: site
    url: https://example.com/rss
    enabled: true
```

RSS 주소를 몰라도 **일반 주소만 넣으면 자동으로 RSS를 찾아봅니다.**
자동 탐지가 실패하면 로그에 안내가 뜨고, 그때는 `selector` 를 추가하면 됩니다:

```yaml
  - name: 공지사항
    type: site
    url: https://example.com/notice
    selector: "table.board a.title"   # 글 제목 링크를 가리키는 CSS 선택자
    enabled: true
```

> 선택자 찾는 법: 크롬에서 해당 페이지 → `F12` → 글 제목 위에서 우클릭 → **검사** →
> 파란색 줄에서 우클릭 → **Copy → Copy selector**

### 잠시 끄기 / 완전히 빼기

- 잠시 끄기: `enabled: true` → `enabled: false`
- 완전히 빼기: 해당 항목 줄들을 지우기 (기록도 자동으로 정리됩니다)

## 키워드 조절

```yaml
keywords:
  mode: any          # any = 하나만 맞아도 통과 / all = 전부 들어있어야 통과
  include: [AI, 인공지능, 파이썬]
  exclude: [광고, 협찬]
```

- `include` 를 **비워두면 전부 통과**합니다 (키워드 필터 없음)
- `exclude` 가 `include` 보다 우선입니다
- ⚠️ **`include` 는 유튜브·사이트에만 적용됩니다.** 뉴스(`news`/`naver`)는 `query` 가 이미
  검색으로 걸러낸 결과이므로 `include` 를 건너뜁니다 — 안 그러면 관련 기사가 대량으로 버려집니다.
  (`반도체` 검색 결과 100건에 `include: [AI, 파이썬]` 을 씌우면 22건만 남습니다.)
  `exclude` 는 뉴스에도 그대로 적용됩니다. 뉴스에도 `include` 를 굳이 걸려면 `filter: true` 를 추가하세요.

### 뉴스 검색어는 넓게 잡으세요

키워드가 **글자 그대로** 들어간 기사만 검색됩니다. `반도체` 하나만 넣으면:

| 검색어 | 결과 중 '반도체' 글자가 없는 것 |
|---|---|
| `HBM` | 99건 중 **83건** |
| `파운드리` | 100건 중 **91건** |
| `TSMC` | 99건 중 **86건** |

즉 `반도체`만 검색하면 이 기사들을 놓칩니다. `OR` 로 묶으세요:

```yaml
    query: '반도체 OR HBM OR 파운드리 OR 웨이퍼 OR TSMC OR D램'
```

실제로 이렇게 바꾸면 좁은 검색이 놓친 44건이 추가로 잡혔습니다.
단 구글은 한 번에 약 100건까지만 주므로, 너무 많이 묶으면 서로 밀어냅니다.
관심 분야가 여럿이면 **소스를 여러 개로 나누는 편**이 낫습니다.
(`OR` 문법은 구글 전용입니다. 네이버는 안 되니 키워드별로 소스를 나누세요.)
- 특정 소스만 다른 키워드를 쓰려면 그 소스 안에 `keywords:` 블록을 넣으세요 (전역 설정을 덮어씁니다)
- 특정 소스만 **키워드 무시하고 전부 받으려면** 그 소스에 `filter: false` 를 넣으세요

## 자주 겪는 상황

| 증상 | 확인할 것 |
|---|---|
| 알림이 하나도 안 옴 | 첫 실행은 원래 안 옵니다. 다음 새 글부터 옵니다 |
| 여전히 안 옴 | **Actions** 탭에서 실행 로그 확인 → `X건 수집`, `전송` 줄을 보세요 |
| `chat not found` | 텔레그램에서 **내 봇에게 먼저 말을 걸었는지** 확인 (1단계 4번) |
| 너무 많이 옴 | `config.yml` 의 `max_items_per_source` 를 줄이거나 `exclude` 키워드 추가 |
| 특정 소스만 안 됨 | 3회 연속 실패하면 텔레그램으로 ⚠️ 경고가 한 번 옵니다 |
| 자동 실행이 멈춤 | GitHub는 **60일간 활동이 없는 저장소의 예약 실행을 중단**합니다. Actions 탭에서 **Enable workflow** 를 누르면 재개됩니다 |
| 같은 뉴스가 두 번 옴 | 링크와 제목으로 중복을 걸러내지만, 언론사마다 헤드라인이 다르면(같은 사건, 다른 제목) 구분할 수 없습니다 |
| 유튜브 알림만 안 옴 | 영상 제목·설명에 `include` 키워드가 없으면 걸러집니다. 그 채널은 전부 받으려면 `filter: false` 추가 |
| 네이버 소스만 안 옴 | 로그에 `건너뜀 — 네이버 API 키가 없습니다`가 있는지 확인 → Secrets 등록 필요 |
| 알림 주기를 바꾸고 싶음 | `.github/workflows/watch.yml` 의 `cron: "*/30 * * * *"` 수정 |

> 예약 실행은 GitHub가 바쁠 때 5~15분 늦어질 수 있습니다. 정상입니다.

### 실제 전송 없이 시험해 보기

**Actions → 알림 봇 → Run workflow** 에서 **dry_run** 을 체크하고 실행하면,
텔레그램으로 보내지 않고 "무엇이 갈 뻔했는지"만 로그에 남습니다. 기록도 건드리지 않습니다.

## 밤에 알림음 끄기

```yaml
telegram:
  timezone: Asia/Seoul
  quiet_hours: "23:00-07:00"
```

이 시간대에는 **알림이 안 오는 게 아니라 소리 없이** 옵니다. 놓치는 글은 없습니다.

## 구조

```
config.yml                     ← 평소에 고치는 건 이 파일뿐
state/seen.json                ← 이미 보낸 글 기록 (자동 관리, 건드리지 마세요)
.github/workflows/watch.yml    ← 실행 주기
watcher/
  main.py                      ← 전체 흐름
  config.py  filters.py        ← 설정 읽기 / 키워드 판정
  state.py   telegram.py       ← 중복 방지 / 전송
  sources/                     ← youtube.py, news.py, site.py, feed.py
```
